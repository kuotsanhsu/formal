# Project Instructions

These instructions apply to the whole repository.

## Writing Conventions

- In Markdown, Lean 4, and chat, write `Gödel`, not `Goedel`, unless quoting an existing filename, external title, or user text exactly.
- Do not add unnecessary hard line breaks inside Markdown paragraphs. The user reads Markdown in VS Code with soft wrapping.
- Keep durable instruction files concise. If this file or similar directory-aware hint files grow long, discuss a revision with the user.

## Git

- The user prefers to perform git operations themselves.
- When a coherent milestone is reached, suggest a commit message in chat.
- Do not stage, commit, push, or create branches unless the user explicitly asks.

## Long-Term Project Memory

- Maintain durable project knowledge in focused Markdown files under `docs/`.
- Consolidate only serious, recurring, or structurally important ideas.
- Discuss major memory consolidations with the user before writing them down.
